# Защита: интеллектуальная проверка ТЗ по 223-ФЗ

Хронометраж 7–8 минут + демо. Один слайд = один абзац ниже.

## 1. Задача (30 с)
На вход — техническое задание; на выход — список проблем с привязкой к фрагменту, категория, объяснение, исправление,
нормативное основание, итоговое заключение. Семь категорий из брифа: противоречие, некорректная характеристика,
код ОКПД 2, гарантия, стандарты, комплектность, ограничение конкуренции.

## 2. Главный принцип: доказательства, а не мнение модели (45 с)
Три уровня. Правила находят дефект. Внутренняя база (нормы 223-ФЗ по частям статей, 420 решений ФАС по доводам,
классификатор ОКПД2, реестр ГОСТ из 46 тыс. пунктов реальных ТЗ, словари) дает основание. Локальная LLM только
формулирует объяснение и правку из переданных доказательств, цитаты проверяются, выдумки отбрасываются.
Ни одного внешнего вызова во время проверки.

## 3. Как читаем документ (45 с)
Не «текст целиком», а структура: разделы, таблицы характеристик (имя → значение), таблицы позиций с ОКПД2,
ключевые поля (предмет, вид договора, гарантия, коды, стандарты). Каждая находка указывает раздел, таблицу, строку.
Поврежденные файлы, DOC/RTF/XLS, PDF — конвертируются или отклоняются с понятной причиной.

## 4. Что ловим (60 с) — показать таблицу из docs/architecture.md §8
Противоречия между таблицей и текстом (тип лифта, грузоподъемность, проем двери). Основание гарантии против вида
договора (накладная vs КС-2/КС-3). Обозначение ГОСТ vs ГОСТ Р. ОКПД2: несуществующий, слишком общий «…190»,
работы vs товары, отсутствует позиция поставляемого оборудования. Комплекты без состава и комплекты, которые надо
раскрыть. Положения, которым не место в ТЗ (нац. режим). Бренд без «или эквивалент», точные габариты, квалификация.

## 5. Результат на кейсовых документах (45 с)
Лифт: 6/6 обязательных правок рецензента найдены, 2/2 необязательных. Метрология: 4/4 и 2/2.
Исправленные версии: 0 ложных ошибок. Все сомнительные случаи помечены «требует проверки», а не «ошибка».
`eval_case.py` воспроизводит эти цифры за секунды.

## 6. Демо (3 мин)
1. Загрузить `lift_source.docx` → заключение «требует доработки», 4 ошибки, открыть противоречие «тип лифта»,
   кликнуть доказательство — текст ч. 10 ст. 4 223-ФЗ.
2. Загрузить `lift_final.docx` → чисто.
3. Загрузить `metrology_source.docx` → комплекты, коды, нац. режим как «ручная проверка».
4. (если успели) включить LLM: показать объяснение с цитатой нормы и правку с плейсхолдером «[значение]».

## 7. Чего система не делает и честные ограничения (30 с)
Не заменяет юриста: применимость норм по датам редакций и внутренние Положения о закупке еще не подключены.
Не знает рынок: «избыточная характеристика» без каталога товаров — всегда «требует проверки».
LLM на CPU медленная (≈1 мин на замечание), поэтому выключена по умолчанию.

## 8. План развития (30 с)
Разметка экспертами 100 выгруженных решений ФАС → обученные классификаторы вместо регексов.
Положения о закупке заказчиков из ЕИС → проверка по внутренним регламентам.
Один класс товаров (лабораторное оборудование) с чек-листом характеристик и каталогом рынка →
проверка избыточных требований по данным, а не по словарю. Перечень СМП (ПП 1352) в базу.

## 9. Развертывание (15 с)
`tar xzf kb_release.tar.gz && docker compose up -d`. Один контейнер, без внешних сервисов, модели опциональны.
